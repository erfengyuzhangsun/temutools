# 个人开发者合规指南（鲸云策 / 自研应用）

> **免责声明**：本文档为产品与运营合规 checklist，不构成法律意见。涉及税务、ICP 备案、公司主体等，请咨询律师或主管部门。

## 一、你没有公司，能不能做？

| 层级 | 结论 |
|------|------|
| **Temu Partner Platform** | 可以。注册类型为 **Developer（开发者）**，个人账号可创建 **自研应用**，不要求营业执照才能提交审核（以平台实际审核为准）。 |
| **服务其他卖家** | 可以。自研应用 = 一套 App Key 服务多店铺；每个卖家在 Temu 卖家中心授权后，你获得该店的 `access_token`。 |
| **中国境内运营网站** | 域名 `www.jinpuhuang.com` 面向公众时，通常需 **ICP 备案**（个人备案或日后主体备案）。与 Temu 审核无直接关系，但是国内合规要点。 |
| **收费** | 个人可提供软件服务并收款，须依法 **纳税申报**（经营所得等）。 |

**不要走错的路线**：第三方服务商（Service Provider）需线下对接 Temu，且常涉及代运营资质；你走的是 **ISV 自研工具**，模式不同。

## 二、客户「合法使用」需要满足什么？（双重授权）

```
┌─────────────────────────────────────────────────────────────┐
│ 第一层：客户 ↔ 你（鲸云策）                                  │
│   注册时同意《用户服务协议》+《隐私政策》                    │
│   绑定店铺时勾选「数据处理授权声明」                         │
└─────────────────────────────────────────────────────────────┘
                              +
┌─────────────────────────────────────────────────────────────┐
│ 第二层：客户 ↔ Temu（平台）                                  │
│   在 Temu 卖家中心对应用「鲸云策」完成官方授权                 │
│   或按平台规则提供有效 Access Token（手动授权）                │
└─────────────────────────────────────────────────────────────┘
```

缺少任一层，都不应处理该店铺 API 数据。

### 跨境卖家（全托管常见）操作路径

1. 客户在 `agentseller.temu.com` → 开放平台 → 客户端管理 → 授权「鲸云策」
2. 复制 Access Token，或在支持回调时走 OAuth 链接
3. 在鲸云策「API 同步」中绑定，并勾选授权声明

### 你（运营者）在审核通过后必须完成

1. Partner Platform 配置 `redirect_url`：`https://www.jinpuhuang.com/api/v1/temu/callback`
2. 服务器 `.env` 配置 `TEMU_APP_KEY` / `TEMU_APP_SECRET` / `TEMU_API_REGION=us`
3. 若服务其他卖家：应用类型设为 **Public** 并完成上架流程（Temu Terms §3.2）

## 四、仍需你本人完成（无法靠代码代替）

| 优先级 | 事项 | 说明 |
|:------:|------|------|
| P0 | Temu US 应用审核通过 | 等待平台 |
| P0 | 配置 redirect + 生产密钥 | 审核通过后立即 |
| P1 | **ICP 备案**（若持续对国内用户运营） | 个人备案：域名 + 服务器 |
| P1 | **客户服务协议**线下留痕 | 付费客户微信/邮件确认服务范围、费用、数据用途（满足 Temu §3.3「书面协议」精神） |
| P1 | 收入 **纳税申报** | 个人经营所得 |
| P2 | 数据安全事件处理流程文档 | 泄露时 72h 内响应客户、按 Temu 要求通知平台 |
| P2 | 可选：注册个体工商户 | 便于开票、备案主体统一（非 Temu 硬性要求） |
